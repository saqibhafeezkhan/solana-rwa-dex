# Analytics service

> **Status: planned.** No code in this directory yet. This file fixes the metric
> definitions before anyone implements them, because "execution quality" is
> ambiguous enough that two dashboards will otherwise disagree.

## Inputs

Everything comes from the indexer (see `services/indexer`), not from RPC directly:

* `markets`, `pool_snapshot` — venue, fee tier, reserves, price over time;
* `order`, `fill` — resting-order lifecycle and executions;
* `settlement_vault` — T+N release/refund status and timing;
* `account_delta` — the tie-breaker when a derived metric disagrees with the UI.

Reference marks for RWA valuations come from `services/oracle`. If a valuation is
stale, every metric derived from it must be labelled, not silently averaged in.

## Metric definitions

Each definition names its inputs and its denominator. All prices are in the
market's quote units; all basis-point figures use 10 000 bps = 100 %.

| Metric | Definition | Why it needs stating |
| :--- | :--- | :--- |
| **Quoted spread** | `(best_ask − best_bid) / mid`, `mid = (best_ask + best_bid) / 2` | Undefined when a book has one side or none; report `null`, never `0` |
| **Effective spread** | `2 · |fill_price − mid_at_fill| / mid_at_fill` | Uses the mid at the fill's slot, not at query time |
| **Slippage (bps)** | `(fill_price − mid_at_submission) / mid_at_submission · 10 000`, signed by side | Separate from fees; mixing them makes venues incomparable |
| **Fee bps realised** | `fees_paid / notional` | AMM fee tiers are per-pool, so aggregate only within a venue |
| **Fill rate** | `filled_orders / placed_orders` | An order cancelled before any fill counts as placed, not filled |
| **Time to fill** | `fill.slot_time − order.create_time` | Reported as a distribution (p50/p90), never a mean alone |
| **Partial-fill ratio** | `partially_filled_orders / filled_orders` | Directly measures whether resting size is too large for the book |
| **Maker participation** | `maker_notional / total_notional` | The metric that tells you whether the order book is actually attracting makers |
| **T+N latency** | `release_time − unlock_slot_time` | Positive means the desk released late; the vault was claimable earlier |
| **Settlement failure rate** | `refunded / (released + refunded)` | Refunds are legitimate, but a rising rate is an operational signal |
| **TWAMM savings** | `naive_notional_cost − twamm_notional_cost` over the same window | Needs a defined naive baseline (single swap at window start), stated in the report |
| **Concentration** | share of volume from the top 1/5/10 wallets | Wallet labels are pseudonymous; never join to KYC identity |

## Outputs

1. **Daily venue report** — per market: volume, maker/taker split, quoted and
   effective spread, fill rate, T+N latency. Markdown plus CSV.
2. **Desk report** — per institution wallet: notional, realised slippage vs
   reference mark, settlement punctuality. Pseudonymous by default; identity
   joins stay off-chain and access-controlled.
3. **Strategy comparison** — TWAMM vs single-shot execution over matched windows,
   with the baseline stated.
4. **Risk feed** — inventory concentration, stale valuation flags, breaker state
   (from the oracle service). Consumed by the risk dashboard, not by traders.

Storage: aggregate tables in the same Postgres as the indexer, exports as Parquet
for anything over ~10⁷ rows. Definitions live in code with unit tests on
hand-built fixtures — a metric that cannot be reproduced from a fixture is not
ready.

## Correctness rules

* **Point-in-time joins.** `mid_at_fill` is the mid at that slot; joining to the
  latest snapshot rewrites history every time the market moves.
* **Finalised data only.** Exclude unfinalised fills from reports; a reorg should
  never move a published number.
* **No double counting across venues.** A single intent executed as two fills on
  two venues is two fills and one intent — say which one a report counts.
* **Nulls are data.** Missing bid, missing reference mark, zero-volume market —
  report `null`/`n/a`, never `0`, or averages silently improve.
* **Decimals at event time.** Convert with the mint decimals snapshotted by the
  indexer, not the decimals read today.
* **Rounding.** Compute in integer base units where possible; convert to display
  units last, and state the rounding direction for bps figures.

## Open decisions

* Whether reports are generated by a batch job (cron) or by queries on demand.
  Start batch: reproducible output, easier to diff.
* Retention: raw `account_delta` forever, aggregates forever, per-slot snapshots
  downsampled after 90 days.
* Whether to publish metrics publicly. If so, the desk report is a separate,
  access-controlled dataset from day one rather than a filtered view later.

## Non-goals

No trading, no signing keys, no valuation authority. Analytics observes; the
valuation desk decides, and the on-chain oracle program remains the only source
of an on-chain price.
